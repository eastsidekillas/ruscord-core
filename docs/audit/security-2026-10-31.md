# Аудит безопасности, 2026-10-31

Вопрос владельца: правильно ли написан код с точки зрения безопасности и не
будет ли утечек. Ниже то, что проверено, что найдено и исправлено, что
остаётся открытым. Проверялись ruscord-core на `main` (25f6ccc) и ruscord-fe
на `master` (8c30e9b).

## Как проверяли

- **Сканеры.**
  - `npm audit` по клиенту.
  - gosec: уже в CI в составе golangci-lint (`.golangci.yml`) и проходит.
  - govulncheck из песочницы не запустился (закрыт Go proxy), поэтому
    добавлен в CI отдельной задачей `vulncheck`.
- **Ручной разбор кода ядра.**
  - Вход и сессии: `internal/auth`.
  - Проверка прав в каждом обработчике REST (61 маршрут `/api/v1`).
  - Доставка событий в gateway (`router.go`, `client.go`).
  - Файлы: `blob`, `imaging`.
  - Ответы с ошибками и логи.
  - Лимиты частоты.
- **Ручной разбор клиента.**
  - Места, где возможен XSS: `innerHTML`, `bypassSecurityTrust*`, привязки
    `[src]`/`[href]`.
  - Хранение токенов.
- **Прогон.** e2e (`e2e/smoke.mjs`) через nginx клиента с новыми
  заголовками. Он падает на любом нарушении CSP. Прошёл 4 раза из 4.

## Что в порядке (проверено по коду)

**Пароли и сессии.**
- Пароли хранятся как argon2id, сравнение за постоянное время.
- Для несуществующего email хешируется фиктивный пароль, чтобы по времени
  ответа нельзя было узнать, есть ли аккаунт.
- Refresh-токен: в базе только его SHA-256, ротация на каждом обновлении.
  Повторное использование старого токена отзывает сессию.
- Access-токен — JWT EdDSA на 10 минут. Алгоритм зафиксирован, поэтому
  подмена на `none` или `HS256` не пройдёт.

**Куки и CSRF.**
- Куки `HttpOnly`, `SameSite=Lax`; `Secure` везде, кроме dev. Токены
  недоступны JavaScript, значит XSS не может их украсть.
- Refresh-кука отправляется только на `/api/v1/auth`.
- CSRF закрывают `SameSite=Lax` и проверка `Origin` на всех изменяющих
  запросах.
- Все GET-маршруты только читают.

**Gateway.**
- WebSocket открывается одноразовым билетом на 30 секунд (ключ в Valkey —
  хеш билета), а не кукой. Origin тоже проверяется.
- RESUME чужой сессии отклоняется: нужен тот же пользователь и та же
  сессия входа (покрыто тестом `TestResume`).
- События фильтрует сервер по снимку прав. Скрытые каналы из gateway не
  выходят.

**Права (нет IDOR).**
- Права считаются на каждом запросе из базы, без кеша. Кик, бан или снятие
  роли действуют сразу.
- Каждый запрос с ID проверяет доступ:
  - канал: `VIEW_CHANNEL`;
  - история: `READ_MESSAGE_HISTORY`;
  - правка сообщения: только автор и только при праве писать сейчас;
  - удаление: автор или `MANAGE_MESSAGES`;
  - `reply_to`: только в том же канале;
  - профиль: только при общем сервере, дружбе или личке;
  - участники группы: только друзья.
- Чужой объект отвечает 404, а не 403 — по ответу не узнать, что объект
  существует.

**Утечки данных.**
- Email и настройки (`User`) уходят только самому пользователю (`/users/@me`,
  READY, `USER_UPDATE` в его личный топик).
- Остальные видят `PublicUser`: id, имя, отображаемое имя, аватар.
- Удалённый аккаунт виден как «Удалённый пользователь».

**Файлы.**
- Формат определяется по содержимому, размер проверяется до декодирования.
- Картинка всегда перекодируется: EXIF с геолокацией и всё, что было в
  файле кроме пикселей, отбрасывается.
- Отдаются с фиксированным типом, `nosniff` и CSP `sandbox`.
- Ключ проверяется регулярным выражением, поэтому обход путей (`../`)
  невозможен.

**SQL.** Все запросы с параметрами (`$1`), склейки пользовательского ввода
в SQL нет.

**Ошибки и логи.**
- Внутренние ошибки наружу уходят как «Внутренняя ошибка».
- В логах нет паролей, токенов и кук.
- Тело запроса ограничено, неизвестные поля JSON отклоняются.

**Лимиты частоты.**
- Есть на вход (по IP и по email), регистрацию, refresh, билеты gateway,
  отправку сообщений, загрузку картинок, заявки в друзья, создание
  серверов, каналов, ролей и приглашений.
- Если Valkey недоступен, запрос отклоняется, а не пропускается без лимита.

**Клиент.**
- Токенов нет в `localStorage`.
- `innerHTML` только для иконок, зашитых в код.
- Пользовательские строки выводятся через интерполяцию Angular, которая
  экранирует HTML.

**Dev-стек.** Все порты на `127.0.0.1`, метрики на отдельном адресе.
