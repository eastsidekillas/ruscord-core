# Журнал разработки

Новые записи сверху. Формат: что сделали, что узнали, что открыто.

## 2026-10-29 · Шаг 2: схема БД и аутентификация

**Сделано**
- Миграции на goose, встроены в бинарь (`migrations/`). В dev применяются при
  старте, в остальных окружениях командой `ruscord migrate`.
- Таблицы `users` и `sessions` (citext для email и username, CHECK на длины).
- `internal/auth`: регистрация, вход, ротация refresh с окном 30 с и отзывом
  сессии при повторном использовании, выход, `/users/@me`, одноразовые тикеты
  для gateway в Valkey (30 с, `GETDEL`).
- `internal/ratelimit`: фиксированное окно на Valkey (`SET NX EX` + `INCR`,
  ключ всегда с TTL).
- `httpx`: единый формат ошибок, разбор JSON с лимитом 1 МиБ и запретом
  неизвестных полей, recover, проверка `Origin`.
- Тесты: 17 в `internal/auth` (unit + интеграционные на настоящем Postgres,
  каждая в своей схеме), лимитер на miniredis. В CI добавлен Postgres-сервис и
  сквозная проверка регистрации через поднятый compose-стек.
- `docs/api.md` с описанием эндпоинтов для фронта.

**Узнали**
- Две вкладки обновляют токен одновременно часто, поэтому строгая ротация без
  окна разлогинивала бы пользователей. Окно 30 секунд закрывает гонку и всё
  ещё ловит украденный токен.
- Лимит попыток на email защищает от перебора, но даёт злоумышленнику
  держать чужой аккаунт в 429 (допущение A9).
- Argon2id на 64 МиБ без ограничения параллельности позволил бы забить память
  сервера пачкой логинов; поставили семафор на 4 хеша.

**Открыто**
- `ClientIP` берёт адрес соединения. За reverse proxy нужен список доверенных
  прокси, иначе лимиты по IP будут общими для всех.
- Access-токен остаётся рабочим до 10 минут после отзыва сессии (осознанно, ADR-0009).
- Нет подтверждения email и восстановления пароля: нужен почтовый провайдер,
  решить до открытой беты.
- Админка и управление сессиями (список устройств, «выйти везде») позже.

## 2026-10-29 · Шаг 1: каркас

**Сделано**
- Go-модуль, точка входа с выбором ролей (`RUSCORD_ROLES`), конфиг из env с
  валидацией: вне dev обязательны пароль Valkey и ключи LiveKit, секрет LiveKit
  не короче 32 символов.
- `/healthz` (процесс жив) и `/readyz` (Postgres, Valkey, NATS). Вне dev
  `/readyz` не отдаёт текст ошибок, чтобы не светить адреса и логины.
- docker compose: Postgres 18, Valkey 9, NATS 2.15 с JetStream, LiveKit v1.13.10.
  Всё на 127.0.0.1, секреты генерирует `make env`.
- CI: vet, тесты с `-race`, golangci-lint, поднятие compose-стека и проверка `/readyz`.
- Документация: архитектура, план, ADR 0001–0010, допущения, чек-лист ревью.

**Узнали**
- Redis 8 распространяется под AGPLv3/SSPL/RSAL. Для self-hosting это не мешает,
  но чтобы не думать о лицензиях вообще, взяли Valkey (BSD) — см. ADR-0010.
- Образ Postgres 18 хранит данные в `/var/lib/postgresql/18/...`, том монтируется
  на `/var/lib/postgresql`.
- Зависимости (pgx, go-redis, nats.go) требуют Go 1.26, поэтому `go.mod` на 1.26.

**Открыто**
- Compose-стек в этой сессии не запускался (нет Docker-демона); его проверяет
  job `compose` в CI. Нужно прогнать `make up && make run` локально.
- Шаг 2: выбрать библиотеку миграций (план: goose) и генерацию SQL (план: sqlc).
