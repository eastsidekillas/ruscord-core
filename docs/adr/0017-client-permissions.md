# ADR-0017: Права для интерфейса считает сервер

- Статус: принято
- Дата: 2026-10-30

## Контекст
Интерфейсу нужны права пользователя, чтобы решать, что показывать: поле ввода
(`SEND_MESSAGES`), удаление чужих сообщений (`MANAGE_MESSAGES`), вход в голос и
демонстрацию (`CONNECT`, `SPEAK`, `STREAM`), настройки сервера и т. д. Почти все
эти решения принимаются на уровне канала, а не сервера.

До этого решения клиент получал только `permissions` сервера (без
переопределений каналов), и в devlog шага 5a было записано, что после смены
ролей клиент пересчитывает его сам. Аудит перед шагом 5b показал:

- прав в канале клиент не получал вообще — ни в READY, ни в REST;
- в клиенте (`ruscord-fe`) нет никакой логики прав, ролей и переопределений:
  пересчёт на клиенте означал бы написать `internal/perm` на TypeScript с нуля
  (26 битов, порядок переопределений, владелец и `ADMINISTRATOR`, неявные
  зависимости) и поддерживать две копии при каждом изменении правил (тайм-ауты,
  голос);
- gateway уже вычисляет права во всех видимых каналах каждой сессии для фильтра
  событий (`guild.View`, ADR-0016), то есть значения есть бесплатно.

Права в интерфейсе — подсказка: каждый REST-запрос проверяет их на сервере.
Ошибка клиента даёт лишнюю кнопку и 403, а не дыру, но расхождение двух копий
алгоритма такие ошибки гарантирует.

## Решение
- В объекте сервера (`guild.Full`: REST, `GUILD_CREATE`, READY) появляется
  `channel_permissions` — права в каждом видимом канале, вычисленные
  `internal/perm` из того же `guild.View`, что и фильтр gateway.
- Gateway сравнивает права сессии до и после каждого события сервера и, если
  они изменились, после диспатчей события отправляет
  `GUILD_PERMISSIONS_UPDATE {guild_id, permissions, channel_permissions}` —
  полная замена обоих полей. Повтор или пропуск промежуточного обновления не
  ломает состояние клиента: последнее всегда верное.
- Клиент права не вычисляет никогда, только проверяет биты.

## Альтернативы
- **Пересчёт на клиенте по ролям и переопределениям.** Протокол не меняется,
  но правила живут в двух местах и на двух языках, а клиент получает данные,
  нужные только для вычисления (переопределения чужих ролей). Отвергнуто.
- **Только `permissions` сервера.** Не решает главного: решения интерфейса
  принимаются по каналу.
- **Дельты вместо полной замены** (только изменившиеся каналы). Меньше байт,
  но клиент должен правильно применять удаление и порядок; полная замена
  проще и устойчива к повторам. Размер ограничен 500 каналами на сервер.

## Последствия
- Объект сервера и события о нём чуть больше: по строке-маске на видимый канал.
- Изменение роли @everyone в большом сервере отправляет каждому подключённому
  участнику одно `GUILD_PERMISSIONS_UPDATE` до ~500 записей.
- Права в личках (`perm.InDM`: блокировка делает личку только для чтения)
  клиенту пока не отдаются: он видит блокировку в связях. Отдать их так же,
  если понадобится.

## Пересмотреть, если
- `GUILD_PERMISSIONS_UPDATE` больше 1 % трафика gateway или средний размер
  больше 16 КиБ: тогда дельты по каналам.
