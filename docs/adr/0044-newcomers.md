# ADR-0044: Ожидание для новых аккаунтов

- Статус: принято
- Дата: 2026-11-07

## Контекст
Ссылку на стрим увидят тысячи людей. Кто-то зарегистрирует десяток
аккаунтов за минуту и начнёт спамить в каналах, личках и заявками в
друзья. Капчи и подтверждения почты нет (провайдер почты в РФ не выбран).
В Discord на этот случай есть «уровень проверки» сервера, например «аккаунт
старше 5 минут».

## Решение
- `RUSCORD_NEWCOMER_WAIT_MIN` (минуты, по умолчанию 0 — выкл.) — сколько
  новый аккаунт ждёт, прежде чем может:
  - писать в каналах серверов;
  - отправлять заявки в друзья;
  - открывать личку с незнакомым (не другом) с общего сервера.
- Возраст аккаунта берётся из его id: это UUIDv7, созданный при
  регистрации. Запрос к базе не нужен. Аккаунт с id другой версии считается
  старым.
- Ответ — 403 `account_too_new` с `retry_after` и сообщением «Новые аккаунты
  могут … через N мин». Клиент показывает отсчёт.
- Не ждут:
  - те, у кого на сервере есть `MANAGE_MESSAGES` или `MANAGE_CHANNELS` (в
    том числе владелец своего нового сервера);
  - ответ на чужую заявку в друзья;
  - личка с другом.
- Реализация: `internal/platform/newcomer`, общая для message и social.

## Альтернативы
- **Уровень проверки на каждый сервер, как в Discord.** Гибче, но нужна
  настройка в интерфейсе и решение по умолчанию для каждого сервера. Пока
  угроза одна — наплыв на бету, — хватает общей настройки.
- **Капча при регистрации.** Сторонние капчи (reCAPTCHA, hCaptcha) — это
  внешние запросы с IP пользователя (152-ФЗ). Своя капча — отдельная
  работа.
- **Подтверждение почты.** Нужен почтовый провайдер (P1 в
  discord-parity).

## Последствия
- Честный новичок со стрима ждёт несколько минут, прежде чем написать на
  сервере. Читать, ставить реакции и заходить в голос он может сразу.
  Рекомендуемое значение на стриме — 5 минут.
- Поменять ожидание можно только перезапуском ядра.

## Пересмотреть, если
- серверы попросят свои уровни проверки;
- или появится подтверждение почты: тогда ждать стоит до подтверждения, а
  не по часам.
