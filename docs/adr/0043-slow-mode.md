# ADR-0043: Медленный режим в текстовых каналах

- Статус: принято
- Дата: 2026-11-07

## Контекст
На стриме в общий канал одновременно пишут тысячи человек. Общий лимит
(10 сообщений за 10 с на человека) не спасает: читать такую ленту нельзя,
а спамить можно. Модератору нужно одной настройкой замедлить канал, как в
Discord.

## Решение
- `channels.rate_limit_per_user`: секунды от 0 до 21600 (6 ч), 0 — выкл.
  Поле есть в `POST /guilds/{id}/channels` и `PATCH /channels/{id}`, только
  у текстовых каналов. Нужно право `MANAGE_CHANNELS`.
- При отправке в такой канал действует лимит «1 сообщение за окно» по
  ключу канал + пользователь (Valkey, общий `ratelimit`).
  - Ответ — 429 `slow_mode` с `retry_after` и заголовком `Retry-After`.
  - Проверка стоит последней перед записью: отправка, упавшая по другой
    причине, не тратит ожидание.
- Медленный режим не касается тех, у кого есть `MANAGE_MESSAGES` или
  `MANAGE_CHANNELS`: они наводят порядок.
- В личках и группах медленного режима нет.
- Ошибки API получают общее поле `retry_after` (секунды, с округлением
  вверх). Его же теперь отдаёт обычный 429 `rate_limited`.

## Альтернативы
- **Окно, привязанное к моменту последнего сообщения в таблице.** Это лишний
  запрос к базе на каждую отправку, а лимитер уже есть.
- **Медленный режим на весь сервер.** Он грубее: каналу объявлений или
  модераторскому каналу он не нужен.

## Последствия
- Изменение режима действует со следующего сообщения. Уже начатое окно
  доживает со старой длиной.
- Если Valkey недоступен, отправка в медленный канал отвечает ошибкой, как
  и другие лимиты.

## Пересмотреть, если
- понадобится медленный режим для веток или форумов;
- или модераторы попросят исключения по ролям, а не по правам.
