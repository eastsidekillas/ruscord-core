# ADR-0033: Тестовый сервер на одном VPS

- Статус: принято
- Дата: 2026-11-02

## Контекст

План шага 6: «Сервер для проверки: прод-compose, HTTPS, TURN, инструкция
(VPS и домен — у владельца)». Владелец просит подготовить проект к деплою
на тестовый VPS.

Что есть и что известно:
- Локальный стек в `deploy/docker-compose.yml`, его проверяют CI (`compose`,
  `e2e`).
- nginx клиента уже проксирует `/api`, `/gateway`, `/cdn` и `/livekit` на
  одном origin (ADR-0020). Он обращается к LiveKit по имени сервиса.
- Браузер даёт микрофон и экран только по HTTPS.
- LiveKit (документация «Ports and firewall», `config-sample.yaml`,
  проверено 2026-11-02):
  - `rtc.udp_port` пускает весь медиатрафик через один UDP-порт, тогда
    диапазон портов не нужен;
  - `rtc.tcp_port` — запасной путь по TCP;
  - `use_external_ip` находит публичный IP через STUN, `node_ip` задаёт его
    вручную;
  - встроенному TURN нужен TLS-сертификат на `turn.domain`, а без балансира
    его TLS-порт должен быть 443.

## Решение

1. **Один VPS, Docker Compose.** `deploy/staging/compose.yml` накладывается
   поверх локального стека и меняет только то, что отличается. Команды —
   `make staging-*`, инструкция — docs/deploy-staging.md.
2. **HTTPS — Caddy** перед nginx клиента. Он сам получает и продлевает
   сертификат Let's Encrypt. Для `localhost` (CI) использует свой
   локальный центр сертификации.
3. **LiveKit в сети Compose, медиа через один UDP-порт.** Публичны только
   7882/udp (медиа) и 7881/tcp (ICE по TCP). Сигналинг идёт через
   `https://домен/livekit` (nginx), без отдельного домена. Публичный IP —
   через STUN, вручную — `RUSCORD_LIVEKIT_NODE_IP`.
4. **TURN выключен.** Чтобы включить TURN/TLS, нужен отдельный
   поддомен с сертификатом и свободный порт 443 на другом IP (или
   L4-балансир). Для проверки с друзьями из домашних сетей хватает UDP
   и запасного TCP.
5. **Публичны только 80, 443, 7881/tcp, 7882/udp.** Базы, очереди,
   хранилище, ядро и метрики — на 127.0.0.1 или внутри сети Docker.
6. **Миграции при старте ядра** (`RUSCORD_AUTO_MIGRATE=true`): узел один,
   гонки нескольких экземпляров нет.
7. **Сборка на сервере** из `git pull` обоих репозиториев. Реестра образов
   нет.
8. **CI поднимает этот стек** (`staging`): весь e2e через HTTPS Caddy и
   `scripts/staging-check.sh`, тот же, что владелец запускает после деплоя.

## Альтернативы

- **LiveKit в сети хоста с диапазоном портов 50000–60000.** Так рекомендует
  архитектурная заметка для прода. Но nginx клиента тогда не найдёт LiveKit
  по имени, пришлось бы менять его конфиг. Публиковать 10 тысяч UDP-портов
  через Docker тяжело. Для теста одного порта достаточно.
- **certbot вместо Caddy.** Больше ручных шагов: получение, продление,
  перезагрузка nginx.
- **Отдельный prod-compose целиком.** Повторил бы локальный, и они бы
  расходились.
- **Образы в реестре (GHCR) из CI.** Удобно для частых выкладок, но нужны
  токены на сервере. Для теста сборки на месте достаточно.

## Последствия

- Друзья в сетях, где закрыто всё, кроме 443, не получат звук: TURN нет.
- Сборка на сервере требует около 4 ГБ памяти (или swap) и несколько минут
  на обновление.
- Регистрация открыта всем, кто знает адрес.
- Один процесс ядра и один LiveKit: падение сервера — простой.

## Пересмотреть, если

- На проверке у кого-то не проходит звук из-за сети — включить TURN/TLS.
- Выкладки станут частыми — собирать образы в CI.
- Понадобится больше одного узла или чужие пользователи — закрытая
  регистрация, мониторинг, LiveKit в сети хоста с диапазоном портов
  (docs/architecture.md, «LiveKit в проде»).
