# ADR-0039: Поиск по сообщениям

- Статус: принято
- Дата: 2026-11-04

## Контекст
Блок «Сообщения» ([plans/messages.md](../plans/messages.md), часть М5). На
серверах компаний друзей — тысячи и десятки тысяч сообщений. Нужен поиск
по-русски (разные формы слова), по автору, по упоминаниям, по файлам и
ссылкам, и чтобы скрытый канал никогда не попадал в выдачу.

## Решение
**Postgres, без отдельного движка.** Генерируемая колонка `messages.search
= to_tsvector('russian', content) || to_tsvector('simple', content)` с
GIN-индексом:
- `russian` даёт основы слов: «кошки» находит «кошка»;
- `simple` даёт слова как написаны: ники, имена, английские слова, всё,
  чего стеммер не знает.

Запрос — `websearch_to_tsquery` для обеих конфигураций через ИЛИ. Это
синтаксис, к которому привыкли: `"точная фраза"`, `-слово`, `или`.

**Где ищем.**
- `GET /guilds/{id}/messages/search` — по текстовым каналам сервера, где у
  пользователя `READ_MESSAGE_HISTORY`. Список считает guild
  (`Readable`), фильтр по каналу вне него ничего не находит.
- `GET /channels/{id}/messages/search` — по одному каналу или личке.

**Фильтры:** `q`, `author_id`, `mentions`, `channel_id`,
`has=file|image|video|link` (можно несколько), `before`/`after` (RFC 3339).
Нужен текст или хотя бы один фильтр. Новые первыми, по 25, `offset` до
5000. `total_results` считается не дальше 5025 («больше пяти тысяч»
достаточно).

**Переход к найденному.** У истории новый параметр `around=<id>`: половина
страницы до сообщения (вместе с ним), половина после.

**Лимит:** 1 поиск в секунду и 30 в минуту на пользователя.

## Альтернативы
- **Meilisearch, OpenSearch, Typesense.** Ещё один сервис для
  self-hosting, синхронизация индекса, права при выдаче пришлось бы
  повторять. На наших объёмах Postgres хватает.
- **`pg_trgm` (подстроки).** Ищет куски слов и опечатки, но не формы
  слов, а индекс в несколько раз больше. Можно добавить позже как второй
  индекс.
- **Только `russian`.** Ломает ники и английские слова (стеммер их
  калечит); только `simple` — не находит «кошку» по «кошки».
- **Сортировка по релевантности.** Пользователи ищут «то сообщение,
  недавно» — новые первыми, как в Discord.

## Последствия
- Колонка и индекс увеличивают таблицу сообщений примерно на треть;
  миграция переписывает таблицу один раз.
- Поиск по серверу — один запрос с `channel_id = ANY(...)`.
- Имена файлов не ищутся, только фильтр «с файлом».

## Пересмотреть, если
- p95 поиска по серверу больше 300 мс.
- Просят поиск по части слова или с опечатками.
