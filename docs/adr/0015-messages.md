# ADR-0015: Сообщения в отдельном модуле, каналы у владельцев

- Статус: принято
- Дата: 2026-10-29

## Контекст
Каналы живут в двух модулях: каналы серверов в guild, лички в social
(ADR-0014). Сообщения нужны в обоих, с одними правилами отправки, истории и
идемпотентности. Модули не читают чужие таблицы.

## Решение
- Модуль `internal/message` владеет таблицей `messages`. Внешнего ключа на канал
  нет: канал лежит в одной из двух таблиц.
- Права модуль спрашивает у владельцев канала через интерфейсы:
  `guild.ChannelPermissions` (сервер, тип канала, права), затем
  `social.Permissions` (права `InDM`). ID — UUIDv7 в обоих модулях, поэтому
  `/channels/{id}/messages` пробует сначала guild, потом social. Канал, который
  не виден, отвечает 404 в обоих.
- Удаление сообщений вместе с каналом идёт через `hooks.ChannelsDeleted`:
  guild и social вызывают его в транзакции удаления канала, сервера или группы.
  Хук регистрирует `main`, guild и social не импортируют message.
- Идемпотентность: уникальный индекс `(channel_id, author_id, nonce)`. Повтор с
  тем же nonce отвечает 200 с первым сообщением, гонка двух повторов ловится по
  нарушению индекса.
- Отправка не берёт блокировку сервера (ADR-0012): это частая операция, и окно
  между проверкой прав и вставкой — миллисекунды. Правка и удаление
  перепроверяют права на момент действия.
- События: `MESSAGE_*` в `guild.<id>` для каналов серверов и в `channel.<id>` для
  личек. Gateway фильтрует события сервера по `VIEW_CHANNEL` получателя.

## Альтернативы
- Общая таблица каналов-«реестр» с FK из сообщений. Нужен третий владелец
  таблицы, а это ещё один модуль ради одного FK.
- Удалять сообщения асинхронно по событию `CHANNEL_DELETE`. Проще связность,
  но сообщения удалённого канала какое-то время читаются, а обработчик
  событий внутри api появится только с gateway.
- Топик `channel.<id>` для всех каналов. Gateway пришлось бы подписываться на
  каждый канал каждого сервера сессии; по серверу подписок на порядок меньше.

## Последствия
- Удаление канала с большой историей держит транзакцию (и блокировку сервера)
  столько, сколько идёт `DELETE` сообщений (допущение A13).
- Права на каждую отправку считаются из Postgres без кеша (A11).

## Пересмотреть, если
- Удаление канала дольше секунды: тогда помечать канал удалённым и чистить
  сообщения фоновой задачей.
- Отправка p95 выше 150 мс (ADR-0006): тогда кешировать права в Valkey с
  инвалидацией по событиям ролей и переопределений.
