# ADR-0038: Непрочитанное и отметки прочтения

- Статус: принято
- Дата: 2026-11-04

## Контекст
Блок «Сообщения» ([plans/messages.md](../plans/messages.md), часть М4).
Клиенту нужно знать, где есть непрочитанное (жирный канал, точка у
сервера) и где его упомянули (красный счётчик). Отметка должна быть общей
для всех вкладок и устройств пользователя. В плане предлагалось хранить
счётчик упоминаний и увеличивать его в транзакции сообщения. Но тогда
`@everyone` на большом сервере пишет по строке на каждого участника, а
обход этого (считать `@everyone` отдельно) даёт два способа подсчёта.

## Решение
**Хранится только отметка.** `read_states (user_id, channel_id,
last_read_id)`: id последнего прочитанного сообщения (UUIDv7 — порядок в
канале). Отметка двигается только вперёд. Автор сразу прочитал своё
сообщение: отправка двигает его отметку без события.

**Остальное считается при чтении.** `GET /users/@me/read-states` отдаёт
по каждому каналу, где у пользователя `READ_MESSAGE_HISTORY` (и по каждой
личке), три значения:
- `last_read_id`;
- `last_message_id` — один шаг по индексу `messages (channel_id, id DESC)`;
- `mention_count` — сколько из последних 100 непрочитанных сообщений
  пингуют пользователя: по имени, ответом, его ролью или `@everyone`, не
  его собственные.

Окно в 100 сообщений делает подсчёт коротким сканом индекса даже в канале,
который не открывали месяц. Клиент показывает «99+». Без записей на каждое
упоминание.

**Сеть.** Клиент запрашивает read states после READY и после
переподключения, а дальше ведёт их сам:
- `MESSAGE_CREATE` двигает `last_message_id` и, если сообщение пингует
  его, `mention_count`;
- `MESSAGE_ACK` от своих же сессий двигает отметку.

Gateway и READY не меняются: так данные только того, кто их запросил, без
общего снимка.

**Отметить.**
- `POST /channels/{id}/messages/{message_id}/ack` — сообщение должно быть
  в этом канале (иначе 404). Клиент шлёт отметку, когда низ ленты виден, не
  чаще раза в несколько секунд. 30 отметок за 10 с, лишние отбрасываются
  молча.
- `POST /guilds/{id}/ack` — все читаемые каналы сервера до их последнего
  сообщения.

Каждая сдвинувшаяся отметка — `MESSAGE_ACK {channel_id, message_id}` в
топик пользователя.

Права у сервера и лички берутся через интерфейсы: guild отдаёт читаемые
каналы и роли пользователя (`Readable`), social — его лички (`ChannelIDs`).

## Альтернативы
- **Счётчик в `read_states`, растущий при отправке** (план). Fan-out на
  `@everyone` или два вида подсчёта; любая потерянная или повторная
  транзакция сбивает счётчик навсегда.
- **Read states в READY.** Снимок READY общий для сессий и уже
  обслуживает права. Отдельный запрос проще, и упавший подсчёт не мешает
  подключиться.
- **Отметка временем, а не id.** Сравнение с сообщениями того же
  миллисекундного тика неоднозначно; id точнее и уже в индексе.
- **Без окна (точный счёт).** Скан всех непрочитанных в заброшенном
  канале; больше 99 всё равно показывается одинаково.

## Последствия
- Новая таблица; удаление каналов чистит их отметки.
- Канал, который пользователь никогда не открывал, непрочитан, если в нём
  есть сообщения. Новичок сервера видит всё жирным, как в Discord.
- `GET /users/@me/read-states` — два коротких подзапроса на канал. На сотни
  каналов это миллисекунды, на тысячи пересмотреть.
- Отметку пишет каждая отправка (одна строка, без события).

## Пересмотреть, если
- p95 `GET /users/@me/read-states` больше 200 мс.
- Нужны уведомления на телефон: тогда понадобятся счётчики на сервере.
