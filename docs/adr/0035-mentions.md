# ADR-0035: Упоминания и разметка сообщений

- Статус: принято
- Дата: 2026-11-04

## Контекст
Блок «Сообщения» ([plans/messages.md](../plans/messages.md), часть М1).
Сейчас ядро знает только `@everyone`/`@here`: флаг `mention_everyone`
ставится по регулярному выражению, если у автора `MENTION_EVERYONE`.
Непрочитанному (М4) и уведомлениям нужно знать, кого сообщение пингует, и
этот список не должен содержать тех, кого автор пинговать не может.
Разметки нет: клиент показывает текст как есть.

## Решение
**Разметка — только в клиенте.** Ядро хранит исходный текст и никогда не
отдаёт HTML. Клиент строит дерево узлов своим парсером и DOM через
шаблоны; ссылки — только `http(s)`.

**Упоминания в тексте — по id, как в Discord:** `<@user_id>`,
`<@&role_id>`, `<#channel_id>`. Имена меняются, id нет. Ядро разбирает
текст при отправке и правке, пропуская блоки и строки кода (клиент
показывает их как текст, значит, и пинга нет; правило вырезания кода
общее для клиента и ядра), и хранит:
- `mentions uuid[]` — участники сервера (в личке — получатели), до 50
  разных упоминаний вместе с ролями, больше — 422;
- `mention_roles uuid[]` — роли этого сервера, которые автор может
  пинговать: помеченные `mentionable` (новое поле роли, по умолчанию
  false) или любые при `MENTION_EVERYONE`. Id `@everyone` ролью не
  считается: для него есть текст `@everyone`;
- `reply_mention` — ответ пингует автора исходного сообщения
  (`reply_mention` в запросе, по умолчанию true), автор попадает в
  `mentions`. Свой ответ себе не пингует.

Правка проверяет всё заново по текущим правам и составу: потерявший право
не пингует, даже правя старое сообщение. Пинг ответа при правке
сохраняется, если исходное сообщение ещё есть. `<#канал>` ядро не хранит:
это ссылка, а не пинг.

Проверка идёт через интерфейсы: guild отвечает, кто из id участники и
какие роли можно пинговать (`guild.Service.Mentions`), social уже отдаёт
получателей лички вместе с правами.

## Альтернативы
- **Упоминания по имени (`@bob`).** Ломаются при смене имени, неоднозначны
  с ником на сервере; разбор на сервере дороже.
- **Отдельная таблица `message_mentions`.** Удобнее для запроса «где меня
  упомянули», но это запись на каждое упоминание и ещё одна таблица на
  удаление. Массивы с GIN-индексом дают тот же запрос; индекс добавим в
  М4, когда появится запрос.
- **Разметка на сервере (HTML в ответе).** Любая ошибка санитайзера — XSS
  у всех получателей; клиенту всё равно нужен свой разбор для поля ввода.
- **Без `mentionable`, роли пингует только `MENTION_EVERYONE`.** Проще, но
  тогда нельзя завести «@игроки», которых зовёт любой; в Discord поле есть,
  и владельцы серверов его ждут.

## Последствия
- Три колонки у `messages`, одна у `roles`; в сообщении API — `mentions` и
  `mention_roles` (всегда массивы), у роли — `mentionable`.
- Отправка в сервере делает до двух лёгких запросов к guild (участники и
  роли по `ANY`), только если в тексте есть упоминания.
- `mention_everyone` теперь не ставится, если `@everyone` внутри кода.
- Пинг упомянутого, который не видит канал, не мешает: события и
  непрочитанное получают только видящие канал (фильтр gateway, М4).

## Пересмотреть, если
- p95 отправки сообщения с упоминаниями больше 50 мс.
- Владельцы серверов просят пинговать больше 50 человек одним сообщением.
