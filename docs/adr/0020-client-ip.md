# ADR-0020: Адрес клиента за обратным прокси

- Статус: принято
- Дата: 2026-10-31

## Контекст
Лимиты регистрации (5 в час) и входа (20 в минуту) считаются по IP
(ADR-0009). В проде перед ядром стоит nginx клиента (ruscord-fe), и адрес
соединения у всех запросов — адрес nginx. Лимиты по IP стали бы общими на всех
пользователей: шестая регистрация за час — 429 для любого (аудит 2026-10-31, F1).

## Решение
`RUSCORD_TRUSTED_PROXIES` — список адресов и подсетей прокси. Middleware
`httpx.TrustProxies` для запроса от доверенного прокси берёт из
`X-Forwarded-For` самый правый адрес, который сам не доверенный: каждый прокси
дописывает адрес, от которого получил запрос, а всё левее первого недоверенного
мог прислать сам клиент. Запросы от остальных адресов заголовок не читают.
Пустой список (по умолчанию) — заголовок не читается никогда.

## Альтернативы
- **Всегда верить `X-Forwarded-For` или `X-Real-IP`.** Любой клиент без прокси
  подставил бы чужой адрес и обошёл лимиты.
- **Самый левый адрес цепочки.** Его присылает клиент — та же подмена.
- **PROXY protocol.** Требует настройки на обеих сторонах и отдельного
  слушателя; для одного nginx перед ядром избыточно.

## Последствия
- В проде нужно указать адрес nginx (или подсеть docker-сети) в
  `RUSCORD_TRUSTED_PROXIES`; без этого лимиты по IP снова общие.
- Ошибка в списке (слишком широкая подсеть) позволит подменять адрес из неё.

## Пересмотреть, если
Перед ядром появится CDN или балансировщик с собственным заголовком адреса
клиента.
