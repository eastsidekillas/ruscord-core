# ADR-0036: Вложения в сообщениях

- Статус: принято
- Дата: 2026-11-04

## Контекст
Блок «Сообщения» ([plans/messages.md](../plans/messages.md), часть М2).
Решения владельца: любые файлы, до 25 МиБ каждый. Хранилище из ADR-0019
рассчитано на картинки до 8 МиБ: `Put` и `Get` держат файл в памяти (чтение
до 4 МиБ), ключи — по хешу содержимого, все файлы публичны. Для вложений
этого мало:
- 25 МиБ на файл и десяток загрузок одновременно не должны держаться в
  памяти;
- файлы закрытого канала не должны открываться по ссылке у того, кто
  потерял доступ;
- видео нужно перематывать (Range);
- любой файл — враждебный ввод: HTML и SVG не должны исполниться на нашем
  домене.

## Решение
**Загрузка — отдельно от сообщения.** `POST /channels/{id}/attachments?filename=…`
с файлом в теле и `Content-Length` (без него 411, больше 25 МиБ — 413), права
`SEND_MESSAGES` и `ATTACH_FILES`. Ответ — вложение с `id`; сообщение
отправляется с `attachments: [id…]` (до 10), текст может быть пустым.
Привязать можно только свою загрузку в этот же канал, ещё не отправленную и
не старше 50 минут — иначе всё сообщение 422. Так у отправки остаётся
`nonce`, а у клиента — прогресс и отмена.

**Тело — через временный файл.** Ядро пишет тело на диск (не больше
`Content-Length`), определяет тип по первым 512 байтам
(`http.DetectContentType`, имя и заявленный тип не важны) и отдаёт S3
файл, который можно перемотать: подписи S3 нужно читать тело дважды. В
памяти — только буфер копирования.

**Что показывается в ленте.** PNG, JPEG, GIF, WebP (размеры читаются из
заголовка без декодирования; больше 8192 по стороне — файлом), MP4 и WebM.
Остальное, SVG и HTML тоже, — файл для скачивания (`.bin` в ключе). Ключ
`attachments/<channel_id>/<id>.<ext>`: id новый на каждую загрузку, ключ
никогда не переиспользуется; расширение задаёт тип отдачи, поэтому тип
переживает бэкап и восстановление.

**Отдача — по подписанной ссылке.** `/cdn/attachments/…?name=&ex=&sig=`:
HMAC-SHA256 от ключа, имени для скачивания и срока, секрет
`RUSCORD_CDN_SECRET` (обязателен вне dev, один на все API-процессы). Срок
округлён до 12 часов и даёт 24–36 часов жизни: в пределах окна ссылка одна и
та же, и браузер её кеширует. История и события всегда несут свежие ссылки.
Без подписи, с чужим именем или просроченная — 404, как несуществующий файл.
Заголовки — как у аватаров (`nosniff`, `CSP: sandbox`), плюс
`Content-Disposition: attachment` для всего, что не показывается, и
`inline` с именем для картинок и видео. Range — через S3 (`206`,
`Content-Range`, `416` вне файла).

**Удаление.** Загрузку ставит в очередь сборщика на час (как ADR-0019),
привязка переносит её на сутки после удаления. Удаление сообщения, канала,
сервера или группы удаляет строки вложений, включая неотправленные, и ставит
их файлы на сутки в той же транзакции. Проверка ссылок для вида `attachments`
убирает строку загрузки, которую так и не отправили: окно привязки (50 мин)
короче, чем час до сборки, поэтому привязать её уже нельзя.

**Лимиты.** 25 МиБ на файл, 10 на сообщение, 100 загрузок и 1 ГиБ в час на
пользователя (у лимитера появился счёт не по одному: `AllowN`).

**Хранилище.** `blob.Store` теперь потоковый: `Put` берёт `io.ReadSeeker` и
размер, `Open` отдаёт тело и диапазон. Аватары и иконки пользуются
`PutBytes`/`ReadAll`; бэкап копирует файлы потоком.

## Альтернативы
- **Файл в той же форме, что сообщение (multipart).** Нет прогресса по
  файлам, повтор после обрыва отправляет всё заново, сложнее `nonce`.
- **Presigned URL и загрузка прямо в S3.** Мимо проверки типа и лимитов;
  SeaweedFS у self-hosting за NAT, и браузеру его адрес не виден.
- **Буфер в памяти вместо временного файла.** 25 МиБ × параллельные загрузки;
  на маленьком VPS это сотни мегабайт.
- **Открытые ссылки, как у аватаров (id в ключе как секрет).** Ссылку из
  закрытого канала открывал бы и выгнанный, вечно. Discord перешёл на
  подписанные ссылки в 2024 году по той же причине.
- **Проверка прав на каждый запрос файла.** Нужна сессия в запросе картинки
  и поход в базу на каждый кадр ленты; подпись проверяется без базы.
- **Подписывать вместе с пользователем.** Ссылки в событиях одни на всех
  получателей; пересылка ссылки другому человеку — то же, что пересылка
  файла, от этого не защищает ничто.

## Последствия
- Новая таблица `attachments`, сообщение может быть без текста; в
  сообщении API — `attachments` (всегда массив).
- Новый обязательный секрет вне dev; `make env` и `make staging-env` его
  генерируют, `make staging-update` подскажет добавить на сервере.
- Лимит тела в nginx клиента (9 МиБ) поднимается до 26 МиБ только для пути
  загрузки (ruscord-fe).
- Открытая больше суток вкладка увидит битые картинки, пока не перечитает
  историю (переподключение, переход в канал); клиент перечитывает при ошибке
  загрузки.
- Временные файлы — в `os.TempDir()` контейнера: до 25 МиБ на загрузку.
- Квот места на сервер нет; объём — в метриках S3 (допущение A28).

## Пересмотреть, если
- Хранилище тестового сервера растёт быстрее 1 ГиБ в неделю на компанию
  друзей — нужны квоты или срок хранения.
- p95 загрузки 25 МиБ в регионе больше 10 с.
- Появится отдельный домен для файлов (тогда `sandbox` можно ослабить для
  просмотра PDF в браузере).
